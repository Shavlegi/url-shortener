# Mini Link — ბმულების შემოკლება

Mini Link — უფასო, თვით-ჰოსტინგის ბმულების შემოკლება — **Cloudflare Workers + Cloudflare D1**,
ქართული ინტერფეისით, QR კოდებით და კლიკების სტატისტიკით. ვიზიტორების შესახებ
**არანაირი მონაცემი არ ინახება** (არც IP, არც ქუქი-თრექინგი).

**საჯარო საიტი:** ნებისმიერს შეუძლია ბმულის დამოკლება `minilink.space`-ზე —
რეგისტრაციის გარეშე. **ადმინ პანელი** ცალკე მისამართზეა
(`admin.minilink.space`, ან `*.workers.dev`) — იქ ადმინი ხედავს ყველა ბმულს
და შლის საეჭვოს.

**v2 — მომხმარებლის ანგარიშები (ნებაყოფლობითი):** ვისაც უნდა, რეგისტრირდება
(username + მეილი + პაროლი), მეილზე 6-ნიშნა კოდით ადასტურებს ანგარიშს და
თავის ბმულებს საკუთარ სივრცეში („ჩემი ბმულები") ინახავს. ანონიმური დამოკლება
ისევ მუშაობს — რეგისტრაცია სავალდებულო არ არის. ადმინი ხედავს, ვინ რა ბმული
დაამოკლა, და მართავს მომხმარებლებს (გათიშვა/წაშლა).

> **English summary:** Mini Link — a free, self-hosted URL shortener on Cloudflare Workers + D1,
> with a Georgian UI, QR codes and click stats. No visitor tracking of any kind.
> The public site (minilink.space) lets anyone shorten a link; the admin panel
> (admin.minilink.space) is separate and password-protected. Admin login uses
> PBKDF2-SHA256 + server-side sessions. v2 adds voluntary user accounts with
> email verification (Resend), per-user link spaces, and admin user management.
> See SECURITY.md for the threat model and known limitations.

## შესაძლებლობები

- **საჯარო დამოკლება** — ნებისმიერი ვიზიტორი ამოკლებს ბმულს `minilink.space`-ზე,
  რეგისტრაციის გარეშე (ავტომატური 6-სიმბოლოიანი სახელი; ლიმიტი: 3/წუთი + 10/საათი ერთ IP-ზე)
- **v2 — მომხმარებლის ანგარიშები (ნებაყოფლობითი):** რეგისტრაცია username + მეილი + პაროლი;
  მეილის ვერიფიკაცია 6-ნიშნა კოდით (10 წუთი, 5 მცდელობა); პაროლის აღდგენა მეილზე კოდით;
  საკუთარი სივრცე „ჩემი ბმულები" (მხოლოდ თავისი ბმულები: კოპირება, QR, ჩართვა/გამორთვა, წაშლა);
  ადმინიდან ჩანს თითოეული ბმულის მფლობელი (username ან „ანონიმური") და მომხმარებლების
  მართვა (გათიშვა/ჩართვა, წაშლა — წაშლილი მომხმარებლის ბმულები ანონიმური ხდება
  და მუშაობას აგრძელებს)
- ბმულების შემოკლება ადმინიდანაც — ავტომატური 6-სიმბოლოიანი სახელი ან თქვენი სახელი (3–32 სიმბოლო)
- სახელის ხელმისაწვდომობის შემოწმება და დუბლიკატების აკრძალვა
- QR კოდი ყველა ბმულზე (ბრაუზერში გენერირდება, PNG გადმოწერა)
- ბმულების სია: ძებნა, კოპირება, ჩართვა/გამორთვა, წაშლა, ვადის დაყენება
- კლიკების მთვლელი (D1-ში ატომური `UPDATE ... SET clicks = clicks + 1`)
- კლიკების ისტორია (v3): თითოეული გახსნის დრო (`click_events` — მხოლოდ
  ბმული + დრო, თითო ბმულზე ბოლო 100 გახსნა) — ადმინსა და შესულ
  მომხმარებელს თავისი ბმულებისთვის; IP, User-Agent და სხვა მონაცემები
  არ ინახება (იხ. SECURITY.md, „კონფიდენციალურობა")
- **შენიშვნა ბმულზე (v4):** თითოეულ ბმულს შეიძლება ჰქონდეს მოკლე
  შენიშვნა („CV", „მაღაზია", მაქს. 100 სიმბოლო) — სიაში სათაურივით
  ჩანს მისამართის ნაცვლად; ძებნაც შენიშვნასაც ეძებს; ბექაფშიც ინახება
- **გაზიარება:** თითოეულ ბმულზე WhatsApp / Telegram / Facebook
  ღილაკები + ტელეფონის საკუთარი „გაზიარება" (share sheet)
- **QR შემქმნელი (v5):** საჯარო გვერდზე ცალკე სექცია — QR კოდი
  ნებისმიერი რამისთვის: ბმული, Instagram, Wi-Fi (WPA/WEP/ღია), ტელეფონი,
  ტექსტი, Google შეფასების ბმული; ფერები, ცენტრში ლოგო (სურათი), PNG
  გადმოწერა (512px); კამერით სკანირება (ბრაუზერის BarcodeDetector —
  Chrome Android-ზე; სხვა ბრაუზერში პატიოსანი შეტყობინება); რჩეულები —
  ანონიმურისთვის localStorage-ში, შესული მომხმარებლისთვის სერვერზე
  (`qr_favorites`, `GET/POST/DELETE /api/auth/qr-favorites`).
  QR მთლიანად მოწყობილობაში იქმნება, სკანირებისას ვიდეო არსად
  იტვირთება. **v6: ყოველი შექმნილი QR სერვერზეც იწერება**
  (`qr_history`, `POST /api/qr-log` — შესული მომხმარებლის user_id-ით,
  ანონიმური მფლობელის გარეშე; ლიმიტი 20/წთ + 200/სთ IP-ჰეშზე;
  ძველი არარჩეული ჩანაწერები იჭრება უახლეს ~2000-მდე) — ამიტომ
  ადმინ პანელში ცალკე ტაბი „QR კოდები" — **ყველა** შექმნილი QR
  მფლობელით, ძებნით, QR-ის ჩვენებით (ფერებით) და წაშლით; რჩეულები
  ⭐ ნიშნით; სტატისტიკაში QR რაოდენობა; აქტივობის ფიდში QR ჩანაწერები;
  მომხმარებლის ბარათსა და პროფილში QR რაოდენობა
  (`GET/DELETE /api/qr-favorites`, ადმინის სესია). **v6.2:** მფლობელის
  სახელი მუქ თემაში თეთრი ტექსტით ღია ფონზე უჩინარი იყო
  (`.badge.type` იყენებდა `var(--primary)`-ს, რომელიც მუქ თემაში
  თეთრია) — ახლა ტექსტი ყოველთვის მუქი ლურჯია; მფლობელის სახელზე
  დაჭერა მის პროფილს ხსნის (იგივე მოდალი, რაც მომხმარებლების ტაბში).
- **Telegram ბოტი (v7):** იგივე Worker-ი პასუხობს Telegram-საც —
  `POST /api/telegram/webhook`. ბმულის გაგზავნაზე ბოტი აბრუნებს მოკლე
  ბმულს + QR კოდის PNG-ს (Worker-ში გენერირდება, იგივე vendored
  ბიბლიოთეკით, გარე QR სერვისის გარეშე); `/qr <ტექსტი>` — QR კოდი
  ნებისმიერი ტექსტისთვის. იგივე მკაცრი ვალიდაცია, რაც საჯარო ფორმაზე;
  ლიმიტი მომხმარებელზე: 3/წუთი + 10/საათი (ბმულები), 10/წუთი +
  60/საათი (QR). Telegram-ის მომხმარებლის ID არსად არ ინახება —
  ლიმიტებისთვის მხოლოდ მის დღიურ SHA-256 ჰეშს ვიყენებთ. ბოტის ბმულები
  ჩვეულებრივი Mini Link ბმულებია (შენიშვნით „Telegram") და ადმინ
  პანელში ჩანს; ბოტის QR-ები `qr_history`-ში ანონიმურად იწერება.
  ჩართვა: იხ. „5გ" ქვემოთ; secrets-ის გარეშე webhook-ი უმოქმედოა.
- **ადმინ ჩატი (v7.0, v7.1-ში გადაკეთებული):** ინდივიდუალური 1:1 ჩატი ადმინსა და თითოეულ
  მეილზე დადასტურებულ მომხმარებელს შორის — ჩატი ჩანს მხოლოდ
  ვერიფიკაცია გავლილ მომხმარებლებთან (შეზღუდვა სერვერზეა, არა
  მხოლოდ ინტერფეისში). მომხმარებელი წერს ტექსტს (პირველიც მას
  შეუძლია); ადმინი უგზავნის ტექსტს + ფოტოს/ფაილს (მაქს. 1.5 MB —
  D1-ის 2 MB ზღვრის გამო; სურათები გაგზავნამდე ბრაუზერში იკუმშება).
  ადმინ პანელში ცალკე ტაბი „ჩატები": ყველა დადასტურებული
  მომხმარებლის სია წაუკითხავების ნიშნითა და ბოლო შეტყობინების
  წინასწარი ნახვით; მომხმარებელზე დაჭერით იხსნება მიმოწერა
  (ცარიელი — თუ ისტორია არ არის) და არაფერი ავტომატურად არ
  იგზავნება. გახსნილ თრედში „+" მენიუდან იგზავნება ფოტო/ფაილი,
  ლინკი (საკუთარი მოკლე ბმულებიდან ან ნებისმიერი https მისამართი)
  ან QR კოდი (QR ისტორიიდან, სურათად) — ყველაფერი მხოლოდ დაჭერაზე.
  შეტყობინებები 5 წამში ერთხელ
  ახლდება (polling); ცალკე დაყენება არ სჭირდება — ცხრილები
  (`chat_threads`, `chat_messages`, `chat_attachments`) ლაზიურად
  იქმნება, ფაილები D1-ში ინახება (R2 არ გამოიყენება). ჩატი არ არის
  end-to-end დაშიფრული (იხ. SECURITY.md).
- **Turnstile (v4, არასავალდებულო):** Cloudflare-ის უფასო
  „მე ადამიანი ვარ" შემოწმება მხოლოდ საჯარო დამოკლების ფორმაზე —
  ირთვება მხოლოდ გასაღებების დაყენების შემდეგ (იხ. „5ბ" ქვემოთ);
  გასაღებების გარეშე ფორმა ისე მუშაობს, როგორც ადრე
- ექსპორტი/იმპორტი JSON-ით (ბექაფი და აღდგენა)
- ადმინის შესვლა პაროლით (PBKDF2-SHA256, სერვერული სესია, HttpOnly cookie)
- Rate limiting — IP-ის SHA-256 ჰეშით (თავად IP არსად ინახება)
- მხოლოდ `https://` დანიშნულება; სახიფათო სქემები, localhost, შიდა IP-ები,
  სხვა shortener-ები და საეჭვო დომენები იბლოკება

## უფასო ტარიფის ლიმიტები (Cloudflare, 2026)

- **Workers:** დღეში 100,000 მოთხოვნა უფასოა.
- **D1:** 5 GB მონაცემები, დღეში 5 მლნ წაკითხვა / 100,000 ჩაწერა უფასოა.
- **Static Assets:** უფასოა.

### 5გ. Telegram ბოტი (v7, არასავალდებულო)

ბოტი იმავე Worker-ში მუშაობს — ცალკე სერვერი არ სჭირდება (Telegram
webhook-ით უგზავნის განახლებებს; Cloudflare-ის უფასო ტარიფი საკმარისია):

1. Telegram-ში გახსენით **@BotFather** → `/newbot` → სახელი + username
   (უნდა მთავრდებოდეს `bot`-ით) → BotFather ბოტის ტოკენს მოგცემთ.
   **ტოკენი არავის გაუზიაროთ და ჩატში არ ჩაწეროთ.**
2. Cloudflare-ში დაამატეთ ორი secret (ზემოთ, მე-5 ნაბიჯი):
   `TELEGRAM_BOT_TOKEN` (BotFather-ის ტოკენი) და
   `TELEGRAM_WEBHOOK_SECRET` (თქვენი მოგონილი გრძელი შემთხვევითი
   სტრიქონი, მინ. 32 სიმბოლო — მაგ. `openssl rand -hex 32`).
3. Webhook-ის დაყენება — ერთხელ, ბრაუზერის მისამართის ველში გახსენით

   ```
   https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://minilink.space/api/telegram/webhook&secret_token=<SECRET>
   ```

   პასუხი `{"ok":true,...}` ნიშნავს, რომ webhook-ი დაყენდა.
4. ტესტი: ბოტს Telegram-ში `/start` მიწერეთ — მისასალმებელი პასუხი
   უნდა მოვიდეს; მერე ბმული გაუგზავნეთ — მოკლე ბმული + QR უნდა დაგიბრუნოთ.
5. Webhook-ის მოსახსნელად: `https://api.telegram.org/bot<TOKEN>/deleteWebhook`
   (ტოკენი იგივე წესით ჩაანაცვლეთ).

## პაროლის შეცვლა / აღდგენა (თუ დაგავიწყდათ)

შეცვლა (იგივე ნაბიჯები აღდგენისთვისაც):

1. გახსენით `scripts/make-hash.html`, შექმენით ახალი პაროლის ჰეში.
2. Cloudflare dashboard → Worker → **Settings → Variables** → `ADMIN_PASSWORD_HASH`
   secret-ის მნიშვნელობა ახლით ჩაანაცვლეთ → **Save** → **Redeploy** (თუ საჭიროა).
3. შედით ახალი პაროლით.
4. დეშბორდში დააჭირეთ **„ყველა მოწყობილობიდან გამოსვლა"** — ყველა ძველი
   სესია დაიხურება (პაროლის შეცვლა თავისით სესიებს არ ხურავს).

## ბრენდი და დომენი

- **სახელი: Mini Link** — სათაური `public/index.html`-შია; ფერები
  `public/styles.css`-ის `:root` ცვლადებია. შეცვალეთ და ხელახლა დადეპლოით.
- **დომენები:**
  - **minilink.space** (ნაყიდია) — **საჯარო საიტი**: დამოკლების ფორმა, პაროლის გარეშე.
    Cloudflare dashboard → Worker → **Settings → Custom Domains** → **Add Custom Domain** → `minilink.space`.
  - **admin.minilink.space** — **ადმინ პანელი**: შესვლა + დეშბორდი. იმავე ადგილას
    ემატება მეორე Custom Domain-ად (უფასო ქვედომენი, იმავე ზონაში).
  - **`*.workers.dev`** მისამართიც ადმინ პანელს ხსნის (სარეზერვო შესასვლელი).
  - მოკლე ბმულები ყოველთვის `minilink.space/...` სახით იქმნება — იმ შემთხვევაშიც კი,
    როცა ადმინი ქმნის მათ ადმინ პანელიდან (კოდში `CONFIG.publicHost`).
- მოკლე სახელის ფორმატი (6 სიმბოლო) `src/index.js`-ის `CONFIG`-ში იცვლება.
  საჯარო ფორმის ლიმიტები (`publicCreateMaxPerMin` / `publicCreateMaxPerHour`)
  იქვეა.
